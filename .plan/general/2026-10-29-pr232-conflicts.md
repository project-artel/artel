# 화면 PR 충돌과 검토 지적 수정

1. 최신 PR head에서 독립 worktree를 만들고 develop을 merge한다. 공유 폴더와 실행 중 서버 JAR는 변경하지 않는다.
2. 새 런 캔버스·편집 잠금·TC 내용 평가·프로젝트별 TC 번호를 모두 보존해 충돌 3파일을 해결한다. 새 캔버스와 TC 가져오기 창에도 동일 번호 mapping을 연결한다.
3. 과거 빌드 TC 편집의 snapshot 선택, 첫 100개 밖 직접 연결 attempt 평가 캐시, 알림 실패 집계의 미검증 오인 지적을 코드로 확인하고 필요한 수정과 회귀 테스트를 추가한다.
4. 화면 전체 test·typecheck/build·수정 파일 lint·diff check를 실행한다. 정상 push로 기존 PR #232를 갱신하며 merge·force push는 하지 않는다.

위험: develop의 큰 캔버스 재설계와 기존 번호 기능의 의미 충돌. 스텝 순서와 TC 식별 번호를 구분하고 API에는 내부 ID를 보존한다.
